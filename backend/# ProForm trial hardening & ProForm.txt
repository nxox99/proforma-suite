# ProForm trial hardening & ProForma Suite site pricing model — 2026-08-18

## Context
Follow-on from the earlier offline-trial-hardening work (see `claude/export-bugfixes-2026-08-13.md` for the unrelated document-export bug fixes). This session covered two things: (1) hardening ProForm's offline trial/license system against clock tampering and key forgery, and (2) reviewing and fixing the ProForma Suite marketing site (the Cloudflare Pages site that sells DOCX Optimizer, ProForm, and Synthetix-CR) so its copy, links, and purchase flow actually match what was built.

## Key decisions locked in this session
- **Business model: one-time purchase, not subscription.** User explicitly chose this over the site's old subscription-flavored copy. Every app is bought once for a flat price and the license is perpetual (no renewal, no billing cycle). This matches the Cloudflare Worker/Stripe integration already built (`mode: 'payment'`, one-time Checkout).
- **One-time prices — CONFIRMED by user**: DOCX Optimizer $99, ProForm $299, Synthetix-CR $399. Live in `pricing.html`, `store.html`, `index.html`, and `terms.html` §3.
- **Trial length: 30 days**, confirmed multiple times. No registration/email/key is required to start a trial — it begins automatically on first launch of the downloaded app (device-fingerprint + server-anchored, see the trial-hardening design below).
- **Licensing accuracy rewrite approved and done.** The site's `faq.html` and `eula.html` (and `copyright.html`, `terms.html` in smaller ways) previously described a fictional "Hardware ID" scheme (processor/motherboard/NIC-derived, remotely revocable) that never matched what was actually built. Rewritten to correctly describe: a browser-based device fingerprint (canvas + screen + timezone + language + hardwareConcurrency + platform, computed via `buildMid()` in ProForm.html), activation happening inside the app itself (not a separate portal), and **no remote-deactivation/revocation capability** — the signed-token design has no kill-switch.
- **App bundle hosting path — CONFIRMED: `/apps/proform/`** on the same Cloudflare Pages deployment as the marketing site (`site/apps/proform/ProForm.html`, `README.html`, `Manual.html`, `Tutorial.html`, `Legal.html`, plus a prebuilt `ProForm-App.zip` of all five — see below). Full structure and deploy notes written into `backend/SETUP.md` §8.
- **Support form/inbox — implemented.** Two separate things, both requested:
  1. `support.html`'s contact form now POSTs to a new Worker endpoint (`/api/support/send`) which emails the message to `SUPPORT_TO_EMAIL` (a new required secret — set it to Nauman's personal address) via Resend, with Reply-To set to the visitor so replying goes straight back to them. Also fires a best-effort acknowledgment email to the visitor. Previously this was a fake `setTimeout` that always claimed success.
  2. For `support@proforma-suite.com` itself to work as a real mailbox (someone emailing it directly, not through the web form) — that's **Cloudflare Email Routing** (free, dashboard-configured, DNS-level forward to a personal inbox), *not* Resend and *not* a Pages "folder". Resend does have an inbound-email feature but it's webhook/API-driven and is the wrong tool for simple forward-to-Gmail. Documented in `backend/SETUP.md` §3.

## Trial/license hardening design (ProForm.html)
- Server-anchored trial via Upstash Redis (`SET trial:<deviceId> <timestamp> NX`, idempotent first-write-wins) with online re-verification each launch; offline fallback decays a cached server-confirmed `daysLeft` by real elapsed local time — never trusts the local clock outright. Preserves full offline usability.
- ECDSA P-256 signed license tokens (`v1.<payload>.<signature>`, chosen over Ed25519 for `crypto.subtle` compatibility). Public verify-only key is embedded client-side; private key lives only as a Cloudflare Worker secret (`wrangler secret put`), never deployed as a file.
- Removed a hidden Shift+P,R,O,K,E,Y dev-console backdoor that self-computed a valid key client-side — this was a bigger hole than the clock-tampering issue itself.
- Cloudflare Worker (`worker.js`, dependency-free) talks directly to Upstash Redis, Resend, and Stripe REST APIs (no SDKs). Stripe webhook signatures verified manually via HMAC-SHA256. Deployed via `wrangler`, not as a static site file. New required secret this session: `SUPPORT_TO_EMAIL` (see above).

## Site fixes applied this session (across all `site/*.html`)
- **Sitewide bug, found late, fixed everywhere**: nav/footer links pointed to `synthetix-cr.html` but the real file is `synthetixcr.html` (no hyphen) — same class of bug as an earlier `trial-signup.html` vs `trialsignup.html` mismatch fixed in a prior pass. Fixed across all 16 site files.
- Removed orphaned/broken trailing script fragments (`/* Clipboard */ });});` with no matching open) that were genuine `SyntaxError`s in `store.html`, `eula.html`, and `copyright.html` — the latter two meant their consent-banner script silently failed to run at all in-browser.
- Rescoped the absolute "no data is ever sent to our servers" privacy claim (present verbatim in 7+ files) to the accurate version: documents/data stay local; the only exception is licence verification (device ID + timestamp, never content).
- **`index.html` and `store.html` both had a "fake successful purchase" bug**: a purchase modal that opened the payment link in a new tab, then unconditionally redirected the current tab to a "Purchase confirmed!" receipt page after an 800ms timeout — regardless of whether payment actually succeeded. Fixed in both: the modal now navigates the *same* tab straight to `payment.html` (which does the real Stripe Checkout redirect), never assumes success.
- Rewrote `pricing.html` (removed the monthly/annual billing toggle entirely, one static price per app), `store.html` (subscription-flavored modal copy → one-time-purchase copy; added working Buy buttons — previously the purchase modal existed in the DOM with no element ever triggering it), `index.html` (same purchase-flow + copy fixes, plus a stray copy-paste bug where the Synthetix-CR card described a "bundle" that doesn't exist), `faq.html` and `eula.html` (large accuracy rewrites per above), `copyright.html` and `terms.html` (smaller consistency fixes), `downloads.html`/`trialconfirm.html` (leftover "Subscribe to keep access" copy).
- `terms.html` §3 renamed from "Subscription License" to "One-Time License Purchase" and rewritten accordingly; §2 (trial) no longer claims an email/registration is required to start.
- **`downloads.html`'s Download button gap, fixed**: it only downloaded `ProForm.html` alone, but the app's in-app Help menu needs `README.html`/`Manual.html`/`Tutorial.html`/`Legal.html` sitting in the same local folder (relative iframe paths in `openHelpDoc()`). A downloaded-alone `ProForm.html` would have broken Help links offline. Fixed by pre-building `ProForm-App.zip` (all 5 files) and pointing the Download button at that instead.
