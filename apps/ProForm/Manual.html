User Manual

ProForm — Complete reference for all features and workflows

1 Opening the App

Double-click ProForm.html to open it in your default browser. No installation is required. On first launch a welcome screen and terms disclaimer are shown, followed by a documentation menu — click Open ProForm to enter the app. On all subsequent visits the app opens directly.

To return to the Readme, FAQ, User Manual, or Legal disclaimer at any time, click Support in the top toolbar.
2 Fill a Form Tab
Selecting a form

The left sidebar lists all available forms, grouped under Built-in forms and My forms (your custom-built or imported forms). Click any form to load it in the main panel. A dot next to the form name darkens when the form has data, and a percentage badge shows completion progress.

Search

Type in the search bar at the top of the sidebar to filter forms by name, description, or field label. Results also include your Filled Forms sessions, matched by the session's own name or by the name of the form it was filled from — so searching finds both a blank form to fill and any past fill of it you've already saved. Click ✕ to clear the search.

Filling dropdown fields

Click the dropdown and select the appropriate option. If a field has Other (specify) enabled, selecting it reveals a free-text input for a custom answer.

Multi-select checkbox fields

Fields configured as Checkboxes (multi) display a list of tickboxes — tick as many as apply. If Other (specify) is enabled, ticking it reveals a free-text input alongside the checkboxes. A Multi-select badge on the field label identifies these fields.

Conditional subforms

Some fields trigger additional sections when a specific option is chosen. These subforms appear directly below the triggering field and disappear if the selection changes. Fill them in the same way as main fields.

Required fields

Fields marked as required show a small red dot next to their label. If you attempt to export with required fields unfilled, they are highlighted in red and the sidebar flags the form with a count of missing fields.

Info boxes

Some forms include read-only info boxes — italicized notes with no input field, used for instructions or important context. They appear inline with the form but are left out of every export format (plain text, PDF, Word) — exports include only headlines and the answers you selected.

Undo

Press Ctrl+Z (or Cmd+Z on Mac) while filling a form to step back up to 5 recent changes, including field edits and Clear form actions.

Clearing a form

Click Clear form in the bottom action bar to reset all fields on the current form. This does not affect other forms or saved sessions.

3 Build a Form Tab
Selecting a form to edit

The left sidebar lists all built-in and custom forms. Click a form to open it in the editor. Built-in forms are labelled as locked examples and open in a read-only summary view; custom forms open in the full editor.

Creating a new form

Click New form in the builder sidebar header to open a menu with four ways to start:

  • Build a new form — starts from a blank canvas.
  • Build from import — loads a .txt, .doc, or .docx file and opens the cleanup & preview screen (see below). Premium feature.
  • Build from text paste — opens a text box to paste content directly, then the same cleanup & preview screen. Premium feature.
  • Edit a form — scrolls to and highlights the form list so you can pick an existing form to modify.

For a blank form, give it a name and optional description in the Form Details card at the top of the editor.

Adding fields

Click + Add field to add a new field. Click the field card to expand it, then configure:

  • Field label — the text the user sees above the field.
  • Field type — choose Dropdown (single) for one-answer fields, or Checkboxes (multi) for fields where multiple options can be selected. Checkboxes (multi) is a premium feature.
  • Options — enter one option per line in the textarea. Long option lists scroll within the box instead of pushing the rest of the editor off-screen — or click Expand next to the label to edit the full list in a larger window instead.
  • Allow "Other (specify)" — adds a free-text fallback option. On by default for newly added fields; uncheck it if you want to strictly limit answers to the listed options.
  • Mark as required — enforces completion before the form can be Saved (and, in turn, before it can be Exported).
Adding headlines

Click + Add headline to insert a labelled divider between fields. Headlines group fields visually and appear as section labels in exported documents.

Adding info boxes

Click + Add info to insert a read-only note — instructions, context, or guidance shown to the user with no input field attached, displayed in italics. Info box text is for on-screen guidance only and is deliberately left out of every export format (plain text, PDF, and Word) — exports include only headlines and the answers the user actually selected.

Reordering fields

Each field card has a drag handle (six-dot grid icon) on its left edge. Click and drag it to move the field to a new position. Works for both main fields and fields within subforms.

Conditional logic — the basic idea (Premium feature)

Conditional logic lets one answer control what else appears on the form. Instead of showing every field to every person, a field can stay hidden until it's actually relevant — so someone who picks "Individual" never has to scroll past a "Business Name" or "Employer" field meant for someone who picked "Business."

In ProForm, a rule is always built the same way: pick a field with options (a dropdown or a multi-select), pick one of its answers, then decide what that answer does. There are three things a rule can do:

  • Show or hide other fields. The core building block — when the trigger answer is picked, chosen fields appear and others can be hidden.
  • Narrow another field's own options. If the field being shown is itself a dropdown, the rule can also limit which of its options are offered — so picking "Business" might reveal an "Entity type" field that only lists Business-appropriate choices.
  • Reveal a whole subform. One answer can trigger an entire extra section (its own group of fields, which can carry its own conditional logic) — useful when a single answer needs several follow-up questions rather than just one or two. See Subforms, below.

Worth keeping in mind: ProForm builds single-page forms, so conditional logic shows and hides fields on that one page rather than skipping between separate pages, and each rule is anchored to one field's one answer (there's no combining several fields' answers into a single AND/OR condition). Within those bounds, though, a field revealed by one rule can carry its own conditional logic — show/hide and option-narrowing rules of its own — so a chain of "if this, then that" questions is easy to build one step at a time. A field inside a subform works the same way: it gets its own Conditional logic section, scoped to that subform's fields. Subforms themselves are one level deep, though — a field inside a subform can't trigger a further nested subform.

Use the Logic overview link above the field list (appears once a form has any rules) to see every rule in the form drawn out as a flow diagram — each trigger field connects with a line to each of its answers, and each answer connects to whatever it shows, hides, narrows, or reveals, so the whole chain reads as a picture rather than a list of sentences. Subforms appear the same way: every field/answer that reveals a subform draws a line into it, and a subform with no line pointing at it is flagged with a warning, since it would never appear when someone fills the form. A subform's own internal rules are drawn nested underneath it. Click any box in the diagram — a trigger field's name, or a subform box — to jump straight to that field's or subform's card and edit it.

The payoff is a form that feels shorter and easier to finish than it looks on paper: nobody has to read through questions that don't apply to them, and a long form can be built once to correctly handle every case without every person seeing every field.

Setting up a rule (Premium feature)

Inside any expanded field card (with at least two other fields in the form), a Conditional logic section appears at the bottom and guides you through setting up a rule. This works the same way for a field inside a subform — its Conditional logic section lists that subform's other fields as the show/hide targets, scoped to that subform:

  • Click a pill button for the answer you want to build a rule around — e.g. + "Employed". This creates the rule and lists every other field below it (every other field in the form for a top-level field, or every other field in the same subform for a field inside one).
  • For each of those fields, click Show or Hide to set what happens when that answer is picked — clicking one automatically clears the other, and leaving both off means the rule doesn't affect that field. A plain-language summary above the list ("shows X and hides Y") always reflects the current choices.
  • If a field you set to Show has its own dropdown options, a nested checklist appears letting you optionally restrict which of its options are offered.
  • Under each rule, a Subform row lists any subforms already linked to that answer, with a + New subform for "…" button — click it to create a new subform and link it to that answer in one step, instead of creating one separately and linking it by hand. The new subform opens below, ready for you to add its fields.
  • Click Expand next to the section title to work in a larger modal window instead — useful for forms with many fields or answers, since it shows the same rules with more room and no inline scrolling.
Subforms (Premium feature)

Click + Add subform to create a conditional sub-section with its own label and fields. Inside the subform card, use Show this subform when… to link it to a field/option pair: pick a field as a pill button, then pick one of its answers as a pill button — clicking a linked answer again unlinks it. When the user selects that option in Fill Forms, the subform appears beneath it. You can also create and link a subform in one step from directly inside a dropdown field's Conditional logic rule — see the + New subform for "…" button described above.

Saving builder changes

Builder edits are not saved automatically. The status indicator at the top of the builder sidebar shows Unsaved changes in red when there are pending edits. Click Save to persist all changes.

Navigating away from the builder without saving will prompt a browser confirmation dialog.
Built-in forms are locked examples

ProForm ships with a few built-in forms — Client Intake, Property Assessment, and Incident Report — included to demonstrate dropdowns, conditional subforms, and required fields. They open in a read-only summary view and cannot be edited or deleted directly, so they're always available as a reliable reference.

To adapt one for your own use, open it and click Duplicate to customize. This creates a fully independent copy in My forms that you can edit freely — the original example is never affected.

Hiding built-in example forms

Once you're comfortable with how ProForm works, you may not need the example forms cluttering your list. Open a built-in form and click Hide this example form — it disappears from both the Fill a Form sidebar and the Build a Form sidebar (shown dimmed there with a "hidden" label instead). Click the same eye icon again, or reopen it from the dimmed builder list, to bring it back at any time. This is a personal display preference stored in your browser — it doesn't delete or change the form itself.

Importing plain text or a file (Premium feature)

Choose Build from import or Build from text paste from the New form menu. Build from import accepts a .txt, .doc, or .docx file. After loading text, ProForm opens a cleanup & preview screen: it automatically splits the text into blocks, and you select lines (click, shift-click, or drag) and tag them as:

  • Headline — becomes a section title. Consecutive headline lines each stay as their own separate section title, both in the builder and on export — they're never merged into one line.
  • Dropdown block — becomes a field, where the first line is the label and the remaining lines become options. This is also the default for any untagged block.
  • Info box — becomes a read-only note with no input field, always shown in italics.

Selected lines can also be deleted outright. If one block of text should actually become two separate fields, select the line that should end the first field and click Split field here — this inserts a dashed divider at that point; everything below it becomes its own field. Click the × on the divider to undo the split and merge the two back into one.

Click the expand icon next to the screen title (on both Cleanup and Confirm field) to grow the window to full screen for easier work on long or complex text.

Once tagged, click Build fields → to move into a per-field review step (Confirm field) where you can edit each dropdown's name, options, and required status before adding everything to a new or existing form. The full original text stays visible in a panel alongside the review form, with the lines behind the current field highlighted — so you can confirm each field against the source as you go, without losing your place. Use Skip this field to leave a field out, ← Previous to go back and re-edit the field you just accepted, or Accept & next → to move on. If a block was tagged wrong back in Cleanup (e.g. it should have been an Info box, not a Dropdown), click Wrong type? Retag → to jump back to that exact line in Cleanup and fix it — note that this restarts field-by-field review, so anything already confirmed in that pass will need to be reviewed again.

Extra blank lines and non-breaking spaces from Word documents are stripped automatically on import.
.docx import reads paragraph text and detects both bold and italic formatting, pre-tagging it in the cleanup screen — a bold paragraph followed by its own option lines is pre-tagged as a dropdown field header, a bold paragraph standing alone with no options under it is pre-tagged as a Headline (section title), and an italic paragraph is pre-tagged as Info box content. You can still relabel any block by hand before building the form. Tables, images, and other formatting are not imported. Requires a modern browser (Chrome, Edge, or Firefox 113+ / Safari 16.4+); on an older browser use Build from text paste instead.
To import a whole section as its own subform instead of flat top-level fields, select its heading line plus the field paragraphs under it in the cleanup screen and click Subform. The Confirm field step for that selection works differently from a normal field: you can edit the subform's name and each of its own fields (add, rename, or remove options just like any other field), then choose which already-confirmed field and answer reveals it — the exact link the builder's "+ New subform for…" shortcut creates by hand, just set up as part of import. If no field with options has been confirmed yet when review reaches the subform block, you can still accept it and link it afterward in the builder's Conditional logic — the Logic overview will flag it as "not linked yet" as a reminder.
After a brand-new form finishes importing, ProForm may suggest opening a dropdown field and using Conditional logic (see below) to show or hide other fields based on the answer.
Saving a long import partway through

Reviewing a large import field-by-field can take a while. At any point during review — or on the final summary screen — click Save & finish later instead of continuing. This saves only the fields you've actually reviewed and accepted so far as a real form in My forms; nothing you haven't looked at yet is added automatically.

Open that form in the Build a Form tab and you'll see an Import in progress banner showing how many fields are still waiting, and which file (if any) they came from. Click Continue import → to re-enter the review wizard exactly where you left off — reviewing only the remaining fields, which are merged into the same form once approved. You can pause and resume as many times as needed.

Linking a “My Forms” folder (Chrome & Edge) (Premium feature)

The very first time you open ProForm in Chrome or Edge, it offers to set up this folder right away — Set up your backup folder — recommending a folder named My Forms inside your Documents. You can also link one anytime afterward from Link "My Forms" folder in the builder sidebar, or right when you start building or saving. However you get there, linking works both ways: ProForm immediately reads any form files already in that folder — including individual form files it wrote previously, or a bundled backup JSON from Back up my forms — and adds anything it finds to your library, then saves every custom form there as its own .json file going forward. Filled sessions are protected the same way: every named save in Filled Forms is also written into a "Filled Sessions" subfolder inside the same linked folder — no separate folder to link for those.

On every later launch, ProForm asks you to link (or relink) that folder with a single click — a plain, predictable prompt every time, rather than a background attempt that silently succeeds or fails depending on whatever the browser happens to remember. If the browser still trusts the folder, that click is effectively instant (a quick permission re-confirmation, not a fresh folder picker); if it doesn't, the same click reopens the picker in the same place with nothing lost, since the actual files are still sitting untouched on your disk either way. Choose Not now on either prompt to skip it for that visit — the first-launch setup prompt won't ask again once declined, while the every-launch relink prompt returns next time, since it reflects a folder you've already chosen to keep linked.

The first time you click Build a Form without a folder linked yet, ProForm also offers to link one right then — before you've typed anything — so new work is protected as a real file from the start rather than only after your first Save. Choose Not now to skip it (you can always link a folder later from the sidebar); this particular prompt only appears once.

This feature relies on the File System Access API, which only Chrome and Edge support. In Safari, Firefox, or on iPhone/iPad, the button is replaced with a short note, and manual backup/restore below works exactly the same as always.
Backing up and restoring your form library

In the builder sidebar, click Back up my forms to download all your custom forms as a single JSON file — keep this somewhere safe. Click Restore backup and choose that JSON file to bring your custom forms back, on this device or a different one. Restoring skips any forms already present, so it's safe to run more than once. This works in every browser, regardless of whether a folder is linked.

4 Saving & Exporting

Saving and exporting are two separate steps, each with its own button in the top-right toolbar: Save, then Export.

Step 1 — Save
The Save button only becomes clickable once every required field in the form has an answer — it stays greyed out until then. Click it, enter a name for this save point (e.g. "Client intake – Acme Corp – Jun 2026"), and confirm. This writes the fill to your Filled Forms library and lights up the Export button next to it.

Step 2 — Export
Click Export and choose a format:

FormatResult
Plain text (.txt) Downloads a .txt file listing each filled field. Multi-select answers appear as a dashed list. Headlines are included as section titles (an empty section's headline is left out); info boxes are left out.
PDF (Premium) Opens the browser print dialog — select Save as PDF as the destination. Headlines are included the same way as plain text; info boxes are left out.
Word document (.doc) (Premium) Downloads a formatted .doc file with table layout, ready to open in Microsoft Word. Multi-select answers appear as bulleted lists inside the table cell. Headlines are included the same way as plain text; info boxes are left out.
Export re-locks itself the instant you edit anything after saving — the current export is always tied to exactly what was last Saved, never a stale answer set. Save again to unlock Export once more.
If any optional (non-required) fields are still blank when you click Export, a dialog lists which ones will be skipped and asks you to confirm before continuing — click Export anyway to proceed. Required fields can never be skipped this way; Save is blocked until they're all filled in.
5 Sessions

Named sessions appear in the Saved sessions panel at the bottom of the Fill Forms sidebar.

  • Click a session name to load it — this restores all field values and switches to the form that was active when it was saved.
  • Click the ✕ next to a session to delete it permanently.
  • Multiple sessions can be saved for the same form, each with a different name.
  • Sessions survive browser restarts as long as browser local storage is not cleared, and permanently if a "My Forms" folder is linked (see Section 3).
  • Each session shows a colored left edge and a percentage — amber for a session still missing some answers, green for one where every field is filled — so a partly finished fill is easy to spot in the list without opening it. The same coloring appears for custom forms with an in-progress fill.
6 Data Storage & Backup

By default, all ProForm form data — every row in the table below — is stored in your browser's localStorage and never sent anywhere. If you link a "My Forms" folder (Chrome/Edge only — see above), your custom forms and named (filled) sessions are additionally saved as individual files in that folder — forms directly inside it, sessions in its "Filled Sessions" subfolder. The one unrelated exception is trial/licence status, covered in Section 7, which involves a minimal device-fingerprint check-in and never includes any of the data below.

DataStorage
Current form answerslocalStorage — auto-saved on every change
Named sessionslocalStorage, plus individual files in the linked folder's "Filled Sessions" subfolder if one is connected
Custom formslocalStorage, plus individual files in your linked "My Forms" folder if one is connected
Required field settingslocalStorage
Clearing your browser's site data or cache will erase all stored sessions and any custom forms that only exist in localStorage. Custom forms and named sessions also saved to a linked "My Forms" folder are unaffected, since they exist as independent files on your device. Built-in forms are always restored from the app itself.

Recommended backup practice:

  • Export completed sessions as Word or text files immediately after filling them in.
  • Periodically use Back up my forms in the Form Builder to download a JSON file of all your custom forms, and store it somewhere outside the browser.
  • In Chrome or Edge, consider linking a "My Forms" folder so custom forms are saved as real files on your device automatically, independent of browser storage.
7 Trial & Activation
30-day free trial

When you first open ProForm, a 30-day free trial begins automatically. During the trial all features are fully unlocked with no restrictions — no payment, no account, no form count. Build as many forms as you like, delete and redo them as often as you need, and use every premium feature freely. Nothing is counted during the trial.

A banner at the top of the app shows how many days remain and a link to activate at any time. The banner can be dismissed for the session.

Each time you open ProForm while online, it sends one small check-in — a device fingerprint and a timestamp, nothing else — to confirm the trial hasn't been reset by clearing browser data or changing your system clock. Nothing about your forms, sessions, or answers is ever included. If you're offline, ProForm keeps working normally from the last confirmed status; it only needs a connection to keep that status accurate, never to function.
Getting an activation key

An activation key unlocks all premium features permanently on your device. To get one:

  1. Click Enter licence key in the top bar of the app (visible during and after the trial).
  2. Click Buy ProForm to pay securely and have your key emailed to you within moments — or Request key by email if you'd rather sort out payment manually first.
  3. Copy the key from your email and paste it into the activation dialog.
  4. Click Apply key. Validation happens instantly, entirely in your browser, and works fully offline from that point on — the app never needs to "phone home" again to confirm an activated licence.

Keys are device-specific — the same key will not work on a different computer, because it's cryptographically tied to that device's fingerprint at the point of purchase. If you need ProForm on a second device, buy or request a separate key for it. Keys are permanent; keep a copy of the email somewhere safe, as clearing your browser data will erase the stored activation record and require you to re-enter it.

8 Libraries & Save Prompts
My Forms Library tab

The My Forms Library tab in the top navigation bar opens a dropdown panel listing every custom form you have built. Each entry shows the form name, description, and a badge — green with the field count if the form is complete, or red Incomplete if it has no fields yet. Click any entry to open it directly in the builder.

Three sort tabs at the top of the panel — Most used, A–Z, and Newest — reorder the list by how often you've saved a fill for each form, alphabetically by name, or by creation date. The "My forms" section of the sidebar uses the same sort, and your choice is remembered between visits.

Each entry also has a small ✕ on the right — click it to delete that form (with a confirmation first, since this can't be undone) right from the dropdown, with no need to open the builder or, if you've linked a "My Forms" folder, delete the file yourself from outside the app. If a folder is linked, the form's file is removed there too.

Filled Forms tab

The Filled Forms tab opens a dropdown panel listing every named session you have saved via the top-right Save button. Each entry shows the session name, which form it belongs to, the save date, and a completion badge — green Complete if all fields are filled, or amber showing the percentage if the session is a work in progress. Click any entry to resume that session in the Fill tab. By default only your 10 most recent fills are listed; a +N older fills — show all link at the bottom expands the panel to show everything.

Each entry also has a small ✕ on the right, the same as in the sidebar's Saved sessions panel (see Section 5) — click it to delete that saved fill immediately, no confirmation dialog, so a mis-click is only ever one Ctrl+Z-style "oops" away from being avoidable by pausing before you click. If a "My Forms" folder is linked, the session's file is removed from its "Filled Sessions" subfolder too.

Save prompts when navigating away

ProForm watches for unsaved work and prevents you from losing it:

  • Builder with unsaved changes — if you navigate away from the builder with edits that haven't been saved, a dialog appears offering to save them to your library or discard and continue.
  • Fill tab with unsaved answers — while a form has any unsaved answers, ProForm locks every other way to navigate: the tab bar, the My Forms Library and Filled Forms dropdowns, the sidebar form list, other saved sessions, and the search box all grey out and stop responding. The only way out is the top-right Save button (once every required field is filled) or the Discard button next to it, which asks you to confirm before clearing the in-progress answers. Either one unlocks navigation again.
Completion badges

Both libraries use visual badges to show status at a glance:

  • Green — N fields / Complete: the form is fully built, or the session has all fields filled.
  • Amber — N% done: the filled session is a work in progress.
  • Red — Incomplete: the custom form has been created but has no fields added yet.
